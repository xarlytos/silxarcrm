================================================================================
ENCRYPTION ALGORITHM
================================================================================

Cipher: AES-256-GCM (Advanced Encryption Standard, 256-bit)
  - NIST-approved
  - Provides confidentiality + authenticity + tamper detection
  - IV: 128 bits (random, unique per encryption)
  - Auth Tag: 128 bits (GMAC authentication)
  - Salt: 128 bits (unique per record, prevents rainbow tables)

Key Derivation: PBKDF2-SHA256
  - 100,000 iterations (NIST recommendation)
  - Unique salt per record
  - Supports key versioning via encryption_key_id

Storage Format: keyId::ciphertext|iv|salt|authTag
  Example: default-2024-01::SGVsbG8gV29ybGQ=|abc123=|def456=|ghi789=

Security Properties:
  ✅ Confidentiality: AES-256
  ✅ Authenticity: GMAC
  ✅ Integrity: Tamper detection
  ✅ Key Rotation: Version-based support
  ✅ Timing Safety: crypto.timingSafeEqual

SETUP STEPS (4 EASY STEPS)
================================================================================

STEP 1: Generate Master Key
  $ node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
  → Store in secure vault (AWS Secrets Manager, HashiCorp Vault, etc.)

STEP 2: Configure Environment
  Add to .env:
    ENCRYPTION_MASTER_KEY=<your-32-byte-hex-key>
    ENCRYPTION_KEY_ID=default-2024-01
    ENCRYPTION_ENABLE_NEW_RECORDS=false
    ENCRYPTION_AUDIT_LOG=true

STEP 3: Run Database Migrations
  $ psql -U $DB_USER -d $DB_NAME -f prisma/migrations/encryption_migration.sql
  → Creates new columns, tables, and indexes (5 min)

  $ npx ts-node scripts/encrypt-pii.ts
  → Encrypts existing data in batches (2-5 min for ~17k records)
  → Generates: encryption-migration-report.json

STEP 4: Enable for New Records
  Update .env:
    ENCRYPTION_ENABLE_NEW_RECORDS=true
  Restart application

ENCRYPT A SINGLE FIELD:

KEY ROTATION (FUTURE)
================================================================================

When you need to rotate keys:

1. Generate new key:
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

2. Update ENCRYPTION_KEY_ID in .env:
   ENCRYPTION_KEY_ID=v2-2025-01

3. Create re-encryption script (similar to encrypt-pii.ts)
   - Decrypt old records with old key
   - Re-encrypt with new key
   - Update encryption_key_id field

4. Old keys can still decrypt old records (backward compatible)

================================================================================
TROUBLESHOOTING
================================================================================

ERROR: "ENCRYPTION_MASTER_KEY not set"
  → Add to .env: ENCRYPTION_MASTER_KEY=<your-key>

ERROR: "authentication tag verification failed"
  → Data corrupted or using wrong key
  → Verify integrity: encryptionService.verifyIntegrity(encrypted)
  → Restore from backup if necessary

ERROR: Migration timeout
  → Reduce batch size in scripts/encrypt-pii.ts (default: 100)
  → Run during maintenance window
  → Can be resumed (only unencrypted records are processed)

ERROR: Performance degradation
  → Enable key derivation cache (enabled by default)
  → Use decryptRecordsBatch() for large sets
  → Only decrypt when necessary

FORGOT MASTER KEY:
  → Data is unrecoverable if no backups exist
  → ALWAYS store master key in secure vault
  → ALWAYS backup encrypted database
